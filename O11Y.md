# Observability

This document is the reference for the spans the hackspace agent emits via
the `cloudflare:workers` `tracing` binding (private beta). It exists so you
can answer two questions without reading source:

  1. **What span should I look at for this kind of problem?**
  2. **What attributes will be on it?**

## Setup

Tracing is enabled in `apps/agent/wrangler.jsonc` under
`observability.traces.enabled: true`. Traces persist to the Cloudflare
observability platform by default; no sampling rate is configured, so the
worker emits every span. If volume becomes an issue, add
`head_sampling_rate` to that block.

The wrapper lives in two identical files \u2014 `apps/agent/src/tracing.ts` and
`packages/workspace/src/tracing.ts`. Both feature-detect the
`cloudflare:workers` binding at module load; when it's unavailable (tests,
unflagged deploys), every `trace()` call passes through to a no-op so the
code keeps working unchanged.

## Attribute conventions

All custom attributes are namespaced `hackspace.*` to avoid colliding with
anything Cloudflare adds upstream. Three recurring keys carry across most
spans:

| Key | Type | Notes |
|---|---|---|
| `hackspace.thread_id` | string | The agent DO name. Always present on agent-side spans. |
| `hackspace.tool_call_id` | string | AI SDK tool call id. Present on tool / cancel spans. |
| `hackspace.error_kind` | enum | `timeout \| 503 \| abort \| other`. Set automatically by `span.setError()`. |

Errors thrown inside a trace callback are recorded via `setError`, which
sets `hackspace.error_kind` and `hackspace.error` (message, capped at 512
chars) before re-throwing.

Two secret-bearing patterns are scrubbed by `redactSecrets()` before
landing on a span:

  - Artifacts userinfo tokens: `https://x:art_v1_\u2026@host/\u2026`
    \u2192 `https://x:REDACTED@host/\u2026`
  - Webhook query tokens: `?key=\u2026&token=\u2026`
    \u2192 `?key=REDACTED&token=REDACTED`

Anywhere a URL or command goes onto a span, it's already been through this.

## Span catalogue

Spans are listed roughly outermost-to-innermost. When the runtime supports
automatic context propagation, children nest inside whichever ancestor was
active when they opened.

### `agent.onRequest`

Wraps every HTTP request the agent DO services. Dispatcher body is in
`_onRequestImpl`; the span sits at the top of `onRequest` so per-route
spans nest cleanly.

| Attribute | Type | Notes |
|---|---|---|
| `hackspace.thread_id` | string | |
| `hackspace.method` | string | Verb, e.g. `GET`, `POST`. |
| `hackspace.path` | string | URL pathname, redacted, capped at 256 chars. Query string deliberately dropped to keep cardinality low. |
| `hackspace.status` | number | HTTP status of the dispatched response. |

### `agent.beforeTurn`

Synchronous-ish prefix that runs before every model call. Catches the
orphan-tool-call sweep that exists to keep wedged turns from rejecting at
`convertToModelMessages`.

| Attribute | Type | Notes |
|---|---|---|
| `hackspace.thread_id` | string | |
| `hackspace.continuation` | boolean | `true` when this is an auto-continue (post-tool-result, reflection) rather than a fresh user turn. |
| `hackspace.messages` | number | Length of the message history at turn start. |
| `hackspace.orphan_patches` | number | Tool parts patched from `input-available`/`input-streaming` to `output-error: cancelled` this turn. Non-zero means a previous turn wedged. |

### `agent.onChatResponse`

Fires after a chat turn settles. Span boundary covers the synchronous
fanout that schedules four background tasks (duration stamping, summary
kick, reflection injection, mention notifications). The background tasks
themselves keep running after the span closes and emit their own spans
(`agent.runSummary`, etc.).

| Attribute | Type | Notes |
|---|---|---|
| `hackspace.thread_id` | string | |
| `hackspace.status` | enum | `completed \| error \| aborted` from the SDK. |
| `hackspace.continuation` | boolean | Whether this was a continuation turn. |
| `hackspace.parts` | number | Total parts on the assistant message. |
| `hackspace.tool_calls` | number | Tool parts among them. |
| `hackspace.error` | string | Set when status is `error`. |

### `agent.recoverInflightExecs`

Background sweep fired from `onStart`. Reconciles the `_exec_inflight`
table with the sandbox's view of each process and patches dangling tool
parts accordingly. Worth pulling up after a deploy: a recover-spike means
DOs are getting evicted mid-exec.

| Attribute | Type | Notes |
|---|---|---|
| `hackspace.thread_id` | string | |
| `hackspace.inflight_rows` | number | Rows the sweep started with. |
| `hackspace.recovered` | number | Reconciled cleanly. |
| `hackspace.failed` | number | Recovery threw \u2014 row is cleared but the persisted tool part may still be in `output-error`. |

### `agent.runSummary`

Background summary generation for the room sidebar. Scheduled via
`kickSummary` after every new message. Always uses Workers AI Kimi so it
stays cheap and doesn't compete with the chat model.

| Attribute | Type | Notes |
|---|---|---|
| `hackspace.thread_id` | string | |
| `hackspace.messages` | number | Message count when the run started. |
| `hackspace.transcript_bytes` | number | Bytes fed to the summariser; not set when `outcome=cache-hit`. |
| `hackspace.summary_bytes` | number | Bytes returned. Set only on `generated`. |
| `hackspace.outcome` | enum | `cache-hit \| empty-transcript \| generated`. Plus an exception path that sets `error_kind`. |

### `agent.cancelToolCall`

User-initiated cancel through the chat UI's stop button. The `cancelled`
return value already tells the frontend whether anything happened; the
span lets dashboards count cancels per thread or per tool.

| Attribute | Type | Notes |
|---|---|---|
| `hackspace.thread_id` | string | |
| `hackspace.tool_call_id` | string | |
| `hackspace.had_controller` | boolean | `false` means the tool already finished or never registered an abort controller \u2014 a no-op cancel. |

### `tool.exec`

The exec tool's full lifetime, from `startProcess` setup through the
streaming log loop to the trailing `pullDirtyAfter`. Wraps an async
generator via a queue-bridge so the span closes deterministically when
the inner work resolves, even if the AI SDK aborts iteration early.

Workspace-level spans (`workspace.startProcess`,
`workspace.streamProcessLogs`, `workspace.pullDirty`) nest naturally
inside this span when context propagation is on.

| Attribute | Type | Notes |
|---|---|---|
| `hackspace.thread_id` | string | |
| `hackspace.tool_call_id` | string | |
| `hackspace.cwd` | string | Working directory the process spawned in. |
| `hackspace.command` | string | Redacted, capped at 512 chars. |
| `hackspace.process_id` | string | Set lazily after `startProcess` returns; absent when start failed. |
| `hackspace.terminated_by` | enum | `exit \| error \| abort \| start-failed \| stream-error \| stream-closed`. |
| `hackspace.exit_code` | number | When the process exited cleanly. |
| `hackspace.stdout_bytes` | number | From the buffer snapshot; capped at 2 MiB per side. |
| `hackspace.stderr_bytes` | number | Same. |
| `hackspace.pull_duration_ms` | number | Time spent in the trailing `pullDirtyAfter`. Often ~200ms; biggest non-process source of turn latency. |
| `hackspace.pull_failed` | boolean | Set when the pull threw; the VFS is out of sync with the container until the next exec. |

### `container.upgrade`

The WebSocket upgrade from the DO to the workspace-server inside the
container. Wraps the 503-retry loop so dashboards can see how often the
fix from `41932a4` is actually saving turns.

| Attribute | Type | Notes |
|---|---|---|
| `hackspace.port` | number | Workspace-server port (4567 in current builds). |
| `hackspace.attempts` | number | 1-indexed. A clean first-try 101 is `attempts=1`. Anything `>1` is a 503-retry recovery; `attempts=N` with `final_status != 101` means we burned the whole 90s budget. |
| `hackspace.final_status` | number | HTTP status of the last attempt. |

### `workspace.exec`

Inside `Workspace.exec`. Covers the mutex wait, stub-hydration, push,
container exec, and trailing pull. The `tool.exec` span above is the
agent-side caller; `workspace.exec` is the lower-level scope that
includes the pre-flight VFS push that the tool span doesn't see.

| Attribute | Type | Notes |
|---|---|---|
| `hackspace.cwd` | string | |
| `hackspace.command` | string | Redacted, 512 chars. |
| `hackspace.pushed` | number | VFS changes pushed up to the container before exec. |
| `hackspace.exit_code` | number | |
| `hackspace.stdout_bytes` | number | |
| `hackspace.stderr_bytes` | number | |
| `hackspace.pulled` | number | Files pulled back from the container after exec. |

### `workspace.startProcess`

Same push-then-spawn pre-flight as `workspace.exec`, but for long-running
processes the caller streams logs from separately.

| Attribute | Type | Notes |
|---|---|---|
| `hackspace.cwd` | string | |
| `hackspace.command` | string | |
| `hackspace.pushed` | number | |
| `hackspace.process_id` | string | |

### `workspace.streamProcessLogs`

Only covers the *setup* (stub acquisition, abort wiring, SSE open). The
iterable's runtime gets its own span from the consumer (`tool.exec`).

| Attribute | Type | Notes |
|---|---|---|
| `hackspace.process_id` | string | |

### `workspace.pullDirty`

The bidirectional VFS sync after a container has written files. Used by
both `workspace.exec` (trailing pull) and the standalone `pullDirtyAfter`
that `tool.exec` calls in its `finally`.

| Attribute | Type | Notes |
|---|---|---|
| `hackspace.pull_path` | enum | `v2` (manifest-aware, current container) or `legacy` (older container images that predate `pullDirtyV2`). |
| `hackspace.pulled_files` | number | Files applied to the VFS. |
| `hackspace.mirrored_files` | number | Writable-mount changes mirrored to R2. |
| `hackspace.max_rev` | number | Revision watermark the pull advanced to. |

### File method spans

`Workspace.readFile`, `writeFile`, `mkdir`, `deleteFile`,
`listFilesUnder`, `findFiles`, `grep`. The agent's `read` / `write` /
`edit` fs-tools tools route through these, so the tool calls trace
without any agent-side changes.

| Span | Key attributes |
|---|---|
| `workspace.readFile` | `path`, `bytes`, `found` |
| `workspace.writeFile` | `path`, `bytes`, `mode`, `mount` (`vfs` \| mount root) |
| `workspace.mkdir` | `path` |
| `workspace.deleteFile` | `path`, `files_removed` (subtree delete can fan out) |
| `workspace.listFilesUnder` | `path`, `count` |
| `workspace.findFiles` | `path`, `pattern`, `count` |
| `workspace.grep` | `path`, `pattern` (first 128 chars), `ignore_case`, `files_scanned`, `hits` |

`stat` / `readdir` are deliberately not traced: they're synchronous SQL
hits with no IO, and the span overhead would be a measurable fraction of
the operation.

## What's not (yet) traced

  - `WarmPool.getContainer`, `WarmPool.alarm`, `WarmPool.releaseAssignment`
    \u2014 Phase 4 of the rollout plan.
  - `Notify.maybeNotifyMentions` \u2014 same.
  - `Agent.onStepFinish` / `afterToolCall` \u2014 fire many times per turn and
    already feed `stampPartDurations`. Tool-level durations land on the
    persisted message parts; tracing them as spans would mostly duplicate
    that signal.
  - Distributed trace propagation across Worker \u2192 DO \u2192 sandbox boundaries
    via W3C `traceparent`. The `cloudflare:workers` tracing module doesn't
    expose a way to attach trace context to outbound `fetch` yet. When the
    API surface lands, the helper here will grow a propagator.

## How to add a new span

```ts
import { trace } from "./tracing.js";

return trace("subsystem.operation", {
  // Eager attributes. Cheap property reads only.
  "hackspace.thread_id": this.name,
  "hackspace.foo": somethingCheap,
}, async (span) => {
  // Lazy attributes. The thunk only runs when the span is being
  // collected, so JSON.stringify / redaction / regex are free
  // off-trace.
  span.set("hackspace.command", () => redactSecrets(cmd).slice(0, 512));
  const out = await doWork();
  span.set("hackspace.bytes", () => out.length);
  return out;
});
```

Conventions when adding a span:

  - Span name: `<subsystem>.<operation>`, lowercase, dot-separated. Match
    the file's namespace (`workspace.*` for workspace methods,
    `agent.*` for lifecycle, `tool.*` for tool-call wrappers,
    `container.*` for sandbox interactions).
  - Always carry `hackspace.thread_id` when the span runs in an agent DO.
    A few minutes of eager-attribute coding now saves a lot of
    `JOIN ON requestId` queries later.
  - Use `span.set(key, () => value)` for anything that costs more than a
    property read.
  - Throw to record errors; `setError` runs automatically and re-throws.
    Catch only when you genuinely want to swallow.
  - Keep attribute values to primitives. The runtime accepts
    `string | number | boolean | undefined` and nothing else.
